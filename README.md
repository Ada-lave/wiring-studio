# Wiring Studio

Локальный редактор монтажных схем на **Svelte 5 + TypeScript** с HTTP MCP и stdio-мостом. Узнаваемые платы и корпуса, провода между конкретными контактами, собственная модель соединений. Интерфейс и Codex работают с одним проектом.

## Запуск

Нужен Node.js 22.12+ и npm. Зависимости зафиксированы в `package-lock.json`.

```bash
npm ci
npm run build
npm start
```

Открыть **http://127.0.0.1:4317**. Для разработки — `npm run dev` (сервер и Vite вместе). `PORT=4320 npm start` меняет порт. Первый запуск создаёт рабочую копию ESP32; исходный пример остаётся в `examples/esp32-led/project.json`.

Для серверного SVG/PDF нужен Chromium. На этой машине автоматически используется `/usr/bin/chromium`. На другой машине выполнить `npx playwright install chromium` либо задать абсолютный `CHROMIUM_PATH`.

## Что можно делать

- Создавать пустые проекты или копии ESP32, импортировать JSON и экспортированный KiCad XML с необязательным `layout.json`.
- Добавлять детали из библиотеки, перетаскивать, поворачивать, удалять, редактировать номинал, корпус, контакты, источник и допущения.
- Нажать **Провод**, затем два контакта. Если оба принадлежат разным сетям, редактор отдельно предложит объединить сети целиком.
- Выбрать контакт, отключить его, назначить/снять NC, переименовать сеть и выбрать её слой.
- Искать по обозначению, подсвечивать сети, включать слои питания/GND/DATA, увеличивать корпуса, масштабировать и перемещать поле.
- Отменять и повторять изменения; история сохраняется при перезапуске. Экспортировать JSON, SVG, PDF A2 и автономный HTML с просмотром, слоями, поиском и локальным перемещением деталей.

Координаты и электрические сети разделены. Перемещение и поворот не меняют номера выводов или подключения. Сохраняется каждый принятый сервером шаг; состояние вида хранится отдельно в браузере. Условные физические контакты отмечены `?`, NC — крестиком и подписью. Компоненты показаны со стороны установки, размеры иллюстративные, а не в миллиметрах.

**Изменённый импорт — самостоятельный проект.** Обратной записи в KiCad и проектирования PCB нет. Кнопка «Проверить» проверяет целостность модели; это не симуляция и не ERC. Импортированный ERC относится к исходнику и перестаёт помечаться актуальным после любой правки.

## Подключение MCP к Codex

Запустить приложение, затем добавить сервер в настройку Codex:

```toml
[mcp_servers.wiring_studio]
url = "http://127.0.0.1:4317/mcp"
```

Готовый фрагмент — `examples/codex-http.toml`. Применяется через MCP-настройки Codex либо объединяется с пользовательским `config.toml`; существующий конфиг не заменять целиком. Схема настройки проверена по [официальной документации OpenAI](https://developers.openai.com/codex/mcp). Сервер реализован на [официальном MCP TypeScript SDK](https://ts.sdk.modelcontextprotocol.io/server).

Если клиент использует только stdio, доступен мост (сначала также запустить приложение):

```bash
npm run mcp --silent
```

В настройке stdio указать `command = "node"`, а `args` — абсолютные пути к `node_modules/tsx/dist/cli.mjs` и `server/stdio.ts`. Пример — `examples/codex-stdio.toml`. В stdout мост пишет только MCP; ошибки идут в stderr. `WIRING_STUDIO_URL` задаёт адрес HTTP MCP для моста. Второе хранилище мост не создаёт.

Сервер протестирован настоящими MCP-клиентами по обоим транспортам. Он **не добавляется автоматически** в глобальную конфигурацию Codex.

### Инструменты

`list_projects`, `create_project`, `open_project`, `get_library`, `apply_commands`, `add_component`, `update_component`, `remove_component`, `place_component`, `connect`, `disconnect`, `rename_net`, `set_net_layer`, `set_nc`, `set_project`, `set_trunk`, `undo`, `redo`, `validate_project`, `import_kicad_xml`, `export_project`.

Все изменения существующего проекта требуют `id` и `expectedRevision`. Получать ревизию через `open_project`. Параметр `showInBrowser:true` также открывает проект в подключённых вкладках редактора. При `REVISION_CONFLICT` сначала перечитать проект и заново оценить команду. `apply_commands` принимает от 1 до 500 команд и сохраняет их атомарно; ошибка любого шага отменяет весь пакет. Создание нового проекта проверяет уникальность ID.

Пример пакета после `create_project({id:"demo",title:"Два резистора"})`:

```json
{
  "id": "demo",
  "expectedRevision": 0,
  "commands": [
    {"op":"add_component","template":"resistor","ref":"R1","value":"330","x":300,"y":300},
    {"op":"add_component","template":"resistor","ref":"R2","value":"10k","x":650,"y":300},
    {"op":"connect","a":{"ref":"R1","pin":"2"},"b":{"ref":"R2","pin":"1"},"name":"DATA"}
  ]
}
```

`allowMerge:true` в `connect` — явное согласие объединить все контакты двух сетей. Без него возвращается `MERGE_REQUIRED`. NC сначала нужно снять; подключённый вывод сначала отключить перед назначением NC. Отключение удаляет только выбранный контакт из общей сети, оставшиеся контакты сохраняют связь.

`import_kicad_xml` принимает XML и необязательный JSON раскладки **содержимым**, а не произвольным файловым путём. `export_project` возвращает путь в `data/projects/exports/`. Нативные `.kicad_sch` не читаются.

## Данные и устройство проекта

- `shared/model.ts` — типы, Zod-схемы, команды и проверка инвариантов; общий контракт UI/API/MCP.
- `shared/library.json` — 26 векторных шаблонов (включая универсальные диоды, LED, транзисторы, кнопку, потенциометр, катушку, реле, батарею, двигатель и разъёмы); ESP32 DevKitC V4 содержит все 38 выводов по [таблицам Espressif](https://documentation.espressif.com/esp-dev-kits/en/latest/esp32/esp32-devkitc/user_guide.html). Конкретную плату всё равно нужно сверить.
- `src/` — Svelte-интерфейс и SVG-рендерер с ортогональным трассировщиком.
- `server/` — хранилище, API, события SSE, MCP, XML-импорт, автономные экспорты.
- `data/projects/<id>.json` — текущий проект и до 60 снимков отмены/повтора. Формат `schemaVersion:1`, ревизии монотонны. Запись через временный файл и rename; один сервер является единственным писателем.
- `examples/esp32-led/` — исходный пример, XML-нетлист, раскладка и исходный ERC.

Самостоятельный JSON содержит `components` (номиналы и номера выводов), `nets` (состав сетей и NC), `layout.components` (корпуса, позиции, углы и геометрия контактов), документацию и допущения. Отсутствие документации при XML-импорте понижает подтверждённость физической позиции до условной.

API: `GET/POST /api/projects`, `GET /api/projects/:id`, `POST /api/projects/:id/commands`, `POST /api/projects/:id/history`, `GET /api/projects/:id/validation`, `POST /api/import`, `GET /api/projects/:id/export/:format`, `GET /api/library`, `GET /api/events`. Изменения рассылаются SSE всем вкладкам; после восстановления соединения интерфейс перечитывает состояние.

По умолчанию сервер слушает только `127.0.0.1`; Host и Origin проверяются. Произвольные пути в командах не принимаются, DTD/entities в XML запрещены. Это локальное однопользовательское приложение без облачного хостинга и учётных записей.

## Пример ESP32 и ограничения

38 деталей, 116 электрических контактов, 24 соединённые сети, NC на U1.6/U1.8/U1.11. Источник 5 В / 4 А, рабочий бюджет ≤3,6 А: LED ≤3,0 А (по ≤0,60 А на модуль), контроллер ≤0,60 А. Программное ограничение LED обязательно. Предохранитель не является точным ограничителем тока. Медь: магистраль 1,0 мм², ветви 0,5 мм², расчёт длины до 1 м в одну сторону. Полные замечания сохранены в самом проекте.

## Проверки

```bash
npm run check
npm test
npm run build
# При запущенном приложении:
npm run test:browser
```

`npm test` проверяет совпадение каждого контакта ESP32 с XML, NC, команды, поворот, объединение сетей, атомарность, сохранение, конфликты, историю, настоящие HTTP/stdio MCP-клиенты, SSE и все форматы экспорта. Браузерные проверки создают отдельный проект с названием Browser test и отчёт в `test-results/`; основной пример не изменяют.

Результаты последнего прогона и изображения интерфейса находятся в `test-results/`. Для другого адреса проверок: `WIRING_STUDIO_BASE=http://127.0.0.1:4320 npm run test:browser`.
